

######## ZEROGPU

SUMMARY:
The user's existing account can host a second ZeroGPU Space. Free personal accounts may host up to 2 ZeroGPU Gradio Spaces if the email is verified and the account is older than 30 days. Since July 2026 this is also the only free way to create a Gradio Space; CPU Basic Gradio and Docker Spaces need a paid plan.
The quota is per account, not per Space: 5 GPU-minutes a day for a free account and 2 for anonymous callers. It resets 24 hours after first use. On top of that, HF staff reported a limit of 3 runs a day for free users in April 2026, and no newer figure was found. Each @spaces.GPU call counts as one run, so the reader has to synthesize a whole article or chapter per GPU call, not one call per sentence.
The hardware is now a slice of an NVIDIA RTX PRO 6000 Blackwell. The default size `large` has 48 GB VRAM at 1x quota; `xlarge` has 96 GB at 2x quota. The hardware flavor string is still `zero-a10g` (checked against /api/spaces/hardware and `hf repos create --flavor`).
@spaces.GPU defaults to 60 s. In spaces 0.51.3, a `large` request is multiplied by 1.5 before scheduling, so duration=60 asks for 90 s. If the request is larger than the remaining quota, the call is refused. The docs say quota is charged on effective (actual) time. No documented maximum duration for free users was found.
Supported versions: Gradio 4+ (latest 6.31.0, released 2026-10-28), PyTorch 2.8.0, 2.9.1, 2.10.0, 2.11.0, 2.12.1 and 2.13.0, Python 3.12.12 or 3.10.13. requirements.txt and packages.txt (apt-get) work, and ffmpeg is preinstalled. Disk is 50 GB and is wiped on restart. Free Spaces sleep after 48 h without use (gcTimeout 172800 s on running ZeroGPU Spaces) and cannot be configured otherwise.
I tested the Gradio 6.31.0 HTTP protocol locally: upload, then call, then SSE stream, then file download all worked. For private Spaces, send `Authorization: Bearer hf_...` on every request. The HF docs say an authenticated call is charged to the caller's account quota.
Plain FastAPI routes are possible through gr.Server (Gradio 6.10+) or demo.app. A @spaces.GPU function called from such a route runs with no Gradio request context, so no X-IP-Token is forwarded and the call falls into the anonymous pool. Gradio's own server-mode guide says ZeroGPU apps must be called through Gradio API endpoints. Use Gradio endpoints for the GPU work and keep FastAPI routes for CPU-only tasks.
Space creation, uploads, secrets, logs and quota checks all work from the `hf` CLI (huggingface_hub 2.4.0), and the raw REST endpoints are listed below.

RECOMMENDATIONS:
- Make one @spaces.GPU call per long text chunk (a whole article or several minutes of audio), streaming results with a generator or splitting on the CPU side. A free account gets about 3 runs and 300 GPU-seconds a day, so per-sentence calls will hit the limit almost at once.
- Use a dynamic duration (duration=lambda text, *a: min(90, 5 + len(text)/40)) instead of the 60 s default. On 'large', the requested value is multiplied by 1.5 when admission is checked against the remaining quota, so a small request still fits after part of the quota is used.
- Stay on the default 'large' size (48 GB VRAM is enough for any TTS model). Keep packed weights under about 42 GiB so the Space does not silently switch to xlarge at 2x quota.
- Pin the versions in the Space: README sdk_version 6.31.0 and python_version '3.12'; requirements.txt torch==2.9.1 (from the supported list) plus spaces==0.51.3. Put espeak-ng in packages.txt if the model needs phonemes. Use preload_from_hub for model weights so cold starts after the 48 h sleep do not have to download them.
- Have the Rust client (Cloudflare Worker or app) call the Space through /gradio_api/call/<name> with 'Authorization: Bearer <read token>' so the user's own 5-minute quota is charged. Store the token as a Worker secret. Download outputs from the 'url' field and copy them to R2.
- Do not put the GPU path behind a plain FastAPI route (gr.Server @get/@post or demo.app). Route it through a Gradio API endpoint (Blocks api_name or @server.api) so the request context and x-ip-token reach spaces.
- Check the remaining quota from the client before submitting with GET https://huggingface.co/api/spaces/zero-gpu/quota (the token needs the 'Billing > Read billing usage' permission), or with hf spaces zero-gpu quota.
- Make the Space private (allowed for free users; Protected is PRO only), and send the bearer token on the upload, call, SSE and file= requests.
- This subagent did not write notes/ files, to avoid index conflicts with parallel agents. The orchestrator should record the quota numbers (5 min/day, 3 runs/day reported April 2026, 1.5x factor) under notes/ according to the user's notes rule.

RISKS:
- The 3-runs-a-day free limit (staff statement from April 2026) may still apply and may include the owner's own calls. If so, the free ZeroGPU tier allows only about 3 synthesis jobs a day. Verify on the first night by making 4 calls and reading the error text and hf spaces zero-gpu quota.
- 5 GPU-minutes a day bounds total audio output. With a fast TTS model at 20x realtime, that is about 100 minutes of audio a day. With slow expressive models at 1-2x realtime, it is only 5-10 minutes.
- It is not verified that an Authorization: Bearer header on direct HTTP calls (rather than gradio_client) is mapped to the account quota and not the 2-minute anonymous pool. Check the 'free ZeroGPU' wording in a quota error and the quota endpoint after a call.
- A cold start after the 48 h sleep, plus the Space build, can take several minutes. The first request after idle will be slow or time out.
- ZeroGPU hardware changed from A10G/H200 to RTX PRO 6000 Blackwell (sm_120). Older CUDA wheels or custom kernels built without sm_120 support may fail. Use torch >= 2.8 wheels.
- Forum reports from July to October 2026 say some eligible free accounts were not offered ZeroGPU when creating a Space. The user already has one ZeroGPU Space, but creating the second could still be blocked in the UI or API.
- Gradio file URLs point to the Space's temp directory and are lost on restart, so outputs must be downloaded right away.
- Gradio 6.x releases very often (6.31.0 is 2 days old). Pin a version; a slightly older one such as 6.30.x is less likely to carry a fresh regression.

CODE: app.py (ZeroGPU Gradio endpoint, one GPU call per chunk; tested locally on gradio 6.31.0)
import spaces  # must be imported before torch/CUDA
import gradio as gr
import numpy as np
import torch

# model = load_tts().to('cuda')   # at module level, per ZeroGPU docs

def _dur(text, ref_audio=None, voice=None):
    # seconds requested; scheduler multiplies by 1.5 on 'large'
    return int(min(90, 10 + len(text) / 40))

@spaces.GPU(duration=_dur)
def tts(text: str, ref_audio: str | None, voice: str | None):
    sr = 24000
    # wav = model.synthesize(text, ref_audio, voice)  -> np.float32 array
    wav = np.zeros(sr, dtype=np.float32)
    return (sr, wav)

with gr.Blocks() as demo:
    t = gr.Textbox(); r = gr.Audio(type="filepath"); v = gr.Textbox()
    o = gr.Audio(format="wav")
    gr.Button().click(tts, [t, r, v], [o], api_name="tts")

demo.queue(default_concurrency_limit=1).launch()


CODE: HTTP flow with curl (same calls a Rust reqwest client makes)
U=https://<user>-nolabs-tts.hf.space
H="Authorization: Bearer $HF_TOKEN"
# 1. upload reference audio (multipart field name: files) -> ["/tmp/gradio/<hash>/ref.wav"]
P=$(curl -s -H "$H" -F files=@ref.wav $U/gradio_api/upload | jq -r '.[0]')
# 2. submit -> {"event_id":"..."}
E=$(curl -s -H "$H" -H 'Content-Type: application/json' -X POST $U/gradio_api/call/tts \
  -d "{\"data\":[\"Hello there\",{\"path\":\"$P\",\"meta\":{\"_type\":\"gradio.FileData\"}},null]}" | jq -r .event_id)
# 3. SSE: event: generating|complete|error|heartbeat ; data: <json list of outputs>
curl -sN -H "$H" $U/gradio_api/call/tts/$E
# complete data: [{"path":"/tmp/gradio/.../audio.wav","url":"https://.../gradio_api/file=/tmp/gradio/.../audio.wav","orig_name":"audio.wav","meta":{"_type":"gradio.FileData"}}]
# 4. download output
curl -s -H "$H" -o out.wav "<url from step 3>"
# named-param variant: POST $U/gradio_api/call/v2/tts -d '{"text":"hi","ref_audio":null,"voice":null}'

######## TTS_MAINSTREAM

SUMMARY:
Tonight's pick: Kokoro-82M as the fast preset engine and Chatterbox-Turbo as the expressive cloning engine. Both can run in the one free ZeroGPU Space, and their combined requirements resolve with uv (verified).
The ZeroGPU platform has changed. The GPU is now an RTX Pro 6000 Blackwell: half a card with 48 GB is the default, a full 96 GB card costs 2x quota. Only PyTorch 2.8.0 to 2.13.0 and Python 3.10.13 / 3.12.12 are supported. A free account gets 5 GPU-minutes per day, charged to whoever calls the Space (2 minutes for anonymous callers). That quota limits the reader more than model quality does.
Kokoro: pip "kokoro" 0.9.4 (PyPI, 2025-04-05; GitHub main has later unreleased commits). Apache-2.0 code and weights. 54 voices in 9 languages, 24 kHz, no cloning. Needs espeak-ng from apt (packages.txt). Reported 35-100x realtime on a 4060 Ti; it also runs on the Space's CPU, which spends no ZeroGPU quota.
Chatterbox: MIT code and weights. PyPI chatterbox-tts 0.1.7 (2026-03-26) pins torch==2.6.0, which cannot install on ZeroGPU (uv resolution fails with torch 2.8.0, verified). Use the source code vendored into the Space instead, as Resemble's own Turbo demo does with torch 2.11.0 and transformers 4.46.3 on zero-a10g.
Turbo (350M, English) adds tags like [laugh] but ignores exaggeration and cfg_weight. Original (500M, English) has exaggeration and cfg_weight. Multilingual V3 (500M, 23 languages) and Nano (110M) are only on GitHub master, not in the 0.1.7 package.
Chatterbox limits: output is 24 kHz, at most 1000 speech tokens per call (about 40 s), and the reference clip must be longer than 5 s for Turbo. A Perth watermark is always applied.
Qwen3-TTS: pip "qwen-tts" 0.1.1, Apache-2.0 code and weights, 10 languages, 24 kHz. Checkpoints: 0.6B and 1.7B Base (cloning), 0.6B and 1.7B CustomVoice (9 speakers), 1.7B VoiceDesign (there is no 0.6B VoiceDesign). Only the 1.7B CustomVoice and VoiceDesign models take instructions.
Qwen3-TTS works on ZeroGPU: the official Space uses torch 2.8.0, transformers 4.57.3 and sdpa attention. The package does not stream, and a third-party benchmark puts it at about 0.82x realtime on an RTX 4090. At that speed 5 GPU-minutes gives about 4 minutes of audio per day, so it is not usable as the main reader engine.
Artificial Analysis TTS arena (current page): Kokoro 82M v1.0 Elo 1062, rank 62. Chatterbox (open model) 1024, rank 80. "Qwen3 TTS" 929, rank 89, but that row has no open-weights link and is probably Alibaba's API model, so its match to the open checkpoints is unverified. Chatterbox Turbo is not listed.
Unverified figures: Turbo's "up to 6x realtime" is Resemble's own claim, and I found no measured speed for original Chatterbox or for Kokoro on x86 CPU.

CODE: Kokoro on ZeroGPU (app.py fragment; requirements: spaces, torch==2.11.0, kokoro==0.9.4, soundfile; packages.txt: espeak-ng)
import spaces, torch, numpy as np
from kokoro import KModel, KPipeline
REPO = 'hexgrad/Kokoro-82M'
GPU = KModel(repo_id=REPO).to('cuda').eval()   # module level, per ZeroGPU docs
CPU = KModel(repo_id=REPO).to('cpu').eval()    # quota-free path
PIPES = {c: KPipeline(lang_code=c, repo_id=REPO, model=False) for c in 'ab'}

@spaces.GPU(duration=30)
def _run(items, speed):
    return [GPU(ps, ref, speed).cpu().numpy() for ps, ref in items]

def tts(text, voice='af_heart', speed=1.0, use_gpu=True):
    p = PIPES[voice[0]]; pack = p.load_voice(voice)
    items = [(ps, pack[len(ps)-1]) for _, ps, _ in p(text, voice, speed)]
    chunks = _run(items, speed) if use_gpu else [CPU(ps, r, speed).numpy() for ps, r in items]
    return 24000, np.concatenate(chunks)

use serde::{Deserialize, Serialize};
use worker::*;

#[derive(Serialize)] struct Msg { role: &'static str, content: String }
#[derive(Serialize)] struct ChatIn { messages: Vec<Msg>, response_format: serde_json::Value, max_tokens: u32 }
#[derive(Deserialize, Serialize)] struct Row { id: i64, title: String }

#[event(fetch)]
async fn fetch(mut req: Request, env: Env, _ctx: Context) -> Result<Response> {
    let cors = Cors::new().with_origins(["*"])
        .with_methods([Method::Get, Method::Post, Method::Options])
        .with_allowed_headers(["content-type", "authorization"]);
    if req.method() == Method::Options { return Response::empty()?.with_cors(&cors); }
    let resp = match req.path().as_str() {
        "/db" => {
            let rows: Vec<Row> = env.d1("DB")?
                .prepare("SELECT id, title FROM docs WHERE id > ?1")
                .bind(&[0.into()])?.all().await?.results()?;
            Response::from_json(&rows)?
        }
        "/r2" => {
            let b = env.bucket("AUDIO")?;
            b.put("k.txt", b"hello".to_vec()).execute().await?;
            match b.get("k.txt").execute().await? {
                Some(o) => Response::from_body(o.body().unwrap().response_body()?)?,
                None => Response::error("missing", 404)?,
            }
        }
        "/ai" => {
            let text = req.text().await?;
            let input = ChatIn {
                messages: vec![Msg{role:"system",content:"Annotate narration with emotion directions".into()},
                               Msg{role:"user",content:text}],
                response_format: serde_json::json!({"type":"json_schema","json_schema":{"type":"object","properties":{"segments":{"type":"array"}},"required":["segments"]}}),
                max_tokens: 1024 };
            let out: serde_json::Value = env.ai("AI")?.run("@cf/google/gemma-4-26b-a4b-it", input).await?;
            Response::from_json(&out)?
        }
        "/hf" => {
            let mut h = Headers::new();
            h.set("content-type", "application/json")?;
            h.set("authorization", &format!("Bearer {}", env.secret("HF_TOKEN")?.to_string()))?;
            let mut init = RequestInit::new();
            init.with_method(Method::Post).with_headers(h)
                .with_body(Some(r#"{\"data\":[\"hi\"]}"#.into()));
            let mut r = Fetch::Request(Request::new_with_init(
                "https://USER-SPACE.hf.space/gradio_api/call/tts", &init)?).send().await?;
            Response::ok(r.text().await?)? // {"event_id": ...}; then GET .../call/tts/{event_id} (SSE)
        }
        _ => Response::ok("ok")?,
    };
    resp.with_cors(&cors)
}

#[event(scheduled)]
async fn scheduled(_e: ScheduledEvent, _env: Env, _c: ScheduleContext) {}

use wasm_bindgen::{prelude::*, JsCast};
use web_sys::{
    HtmlAudioElement, MediaImage, MediaMetadata, MediaMetadataInit, MediaPositionState,
    MediaSession, MediaSessionAction, MediaSessionActionDetails, MediaSessionPlaybackState,
};

fn session() -> MediaSession { web_sys::window().unwrap().navigator().media_session() }

pub fn set_metadata(title: &str, album: &str, art: &str) {
    let init = MediaMetadataInit::new();
    init.set_title(title);
    init.set_artist("nolabs reader");
    init.set_album(album);
    let img = MediaImage::new(art);
    img.set_sizes("512x512");
    img.set_type("image/png");
    init.set_artwork(&[img]);
    if let Ok(md) = MediaMetadata::new_with_init(&init) { session().set_metadata(Some(&md)); }
}

pub fn set_playback_state(playing: bool) {
    session().set_playback_state(if playing { MediaSessionPlaybackState::Playing } else { MediaSessionPlaybackState::Paused });
}

pub fn set_position(duration: f64, position: f64, rate: f64) {
    let st = MediaPositionState::new();
    st.set_duration(duration);
    st.set_position(position);
    st.set_playback_rate(rate);
    let _ = session().set_position_state_with_state(&st);
}

pub fn install_handlers(audio: &HtmlAudioElement) {
    let s = session();
    let on = |action: MediaSessionAction, f: Box<dyn FnMut(MediaSessionActionDetails)>| {
        let cb = Closure::wrap(f);
        s.set_action_handler(action, Some(cb.as_ref().unchecked_ref()));
        cb.forget();
    };
    let a = audio.clone();
    on(MediaSessionAction::Play, Box::new(move |_| { let _ = a.play(); set_playback_state(true); }));
    let a = audio.clone();
    on(MediaSessionAction::Pause, Box::new(move |_| { let _ = a.pause(); set_playback_state(false); }));
    let a = audio.clone();
    on(MediaSessionAction::Seekbackward, Box::new(move |d: MediaSessionActionDetails| {
        let off = d.get_seek_offset().unwrap_or(10.0);
        a.set_current_time((a.current_time() - off).max(0.0));
    }));
    let a = audio.clone();
    on(MediaSessionAction::Seekforward, Box::new(move |d: MediaSessionActionDetails| {
        let off = d.get_seek_offset().unwrap_or(10.0);
        a.set_current_time(a.current_time() + off);
    }));
    let a = audio.clone();
    on(MediaSessionAction::Seekto, Box::new(move |d: MediaSessionActionDetails| {
        if let Some(t) = d.get_seek_time() { a.set_current_time(t); }
    }));
    on(MediaSessionAction::Nexttrack, Box::new(|_| { /* next chunk/chapter */ }));
    on(MediaSessionAction::Previoustrack, Box::new(|_| { /* previous chunk/chapter */ }));
}

const SHELL = "shell-v1";
self.addEventListener("install", e => { self.skipWaiting(); e.waitUntil(caches.open(SHELL).then(c => c.addAll(["/", "/manifest.webmanifest"]))); });
self.addEventListener("activate", e => e.waitUntil(self.clients.claim()));
self.addEventListener("fetch", e => {
  const req = e.request;
  if (req.method !== "GET") return;
  const url = new URL(req.url);
  if (url.origin !== location.origin) {
    e.respondWith(caches.match(req, { cacheName: "audio-v1" }).then(r => r || fetch(req)));
    return;
  }
  if (req.mode === "navigate") { e.respondWith(fetch(req).catch(() => caches.match("/"))); return; }
  e.respondWith(caches.match(req).then(r => r || fetch(req).then(res => {
    if (res.ok) { const copy = res.clone(); caches.open(SHELL).then(c => c.put(req, copy)); }
    return res;
  })));
});
